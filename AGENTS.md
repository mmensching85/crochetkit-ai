# crochetkit-ai — Agent Instructions

## What This Is
A beginner crochet project planner that matches projects to available materials (yarn, hooks) — not the other way around. The core insight: show people what they can make with what they *have*, not what they need to buy.

**Stack:**
- Backend: Node.js, Express 5, JWT auth, bcryptjs, LRU cache
- Frontend: Static HTML/JS/CSS in `public/`
- Data: JSON files in `data/` (patterns, feedback, users, match counts, popular items)
- No database — everything is flat JSON files

## Project Structure
```
server.js              # Main Express server — all routes defined here
src/
  matchPattern.js      # Core matching algorithm — yarn/hook → project recommendations
  formatProjectOutput.js  # Formats match results for API response
  termConverter.js     # Converts crochet terminology (hook sizes, yarn weights etc.)
  test_matcher.js      # Test suite for the matcher
  generate_patterns_json.py  # Python script to regenerate patterns.json from source data
data/
  patterns.json        # The pattern database — DO NOT manually edit, use generate script
  feedback.json        # User feedback on recommendations
  users.json           # User accounts (bcrypt hashed passwords)
  match-count.json     # Usage tracking
  popular.json         # Popular patterns cache
  contacts.json        # Contact form submissions
public/                # Static frontend files
scripts/               # Utility scripts
```

## Critical Rules
- **Never manually edit `data/patterns.json`** — it's generated by `src/generate_patterns_json.py`. Edit the source data and regenerate
- **`data/users.json` contains bcrypt-hashed passwords** — never log or expose this file's contents
- **JWT_SECRET must be set in production** — the default `'crochetkit-secret-key-change-in-production'` is dev-only
- Rate limiting is handled manually in `server.js` via an in-memory `Map` — don't add a second rate limiter
- LRU cache is used in `matchPattern.js` for performance — cache is invalidated via `invalidateCache()`

## Running the App
```bash
node server.js          # start server (port 3000 by default, or PORT env var)
npm start               # same thing
node src/test_matcher.js  # run matcher tests
python3 src/generate_patterns_json.py  # regenerate patterns database
```

## Domain Context (Important for AI)
- **Yarn weight** matters — DK, worsted, bulky etc. are NOT interchangeable
- **Hook size** is usually paired with yarn weight — mismatching causes problems
- **Yardage** is critical — the matcher checks if the user has *enough* yarn for a project
- **Beginner-first** — every output should be accessible to someone who just learned to crochet. Avoid jargon; if used, link to glossary
- Target output: 2-4 curated project recommendations, not a giant list

## Architecture Notes
- `matchPattern.js` is the core — it scores patterns against user's available materials
- `formatProjectOutput.js` shapes the response — if output format needs changing, this is where
- All API routes are in `server.js` — there's no separate router file
- The app is intentionally simple — resist the urge to over-engineer it

## When Adding New Patterns
Always use `generate_patterns_json.py` — never hand-edit `patterns.json`. The generate script normalizes fields, validates yarn weights and hook sizes, and ensures consistent structure.
